## Preview

Build and upload a preview of your project to our testfiles S3 bucket.

Each git branch gets its own preview, so previewing a feature branch won't overwrite the preview someone published from another branch. The URLs are saved [per branch](/graphics-kit-publisher/package/#preview) in your `package.json`.

<Tabs>
  <TabItem label="CLI" icon="setting">
    ```console
    pnpm graphics-publisher preview
    ```
  </TabItem>
  <TabItem label="Graphics kit" icon="laptop">
    ```console
    pnpm preview
    ```
  </TabItem>
</Tabs>

<Aside>
If the publisher can't work out your git branch — a detached `HEAD`, or a directory that isn't a git repo — it warns and publishes to a shared `"_"` preview that everyone else in that state also uses. Set `PUBLISHER_PREVIEW_BRANCH=<name>` to get a path of your own.
</Aside>

## Upload

Upload your project to the graphics server.

<Tabs>
  <TabItem label="CLI" icon="setting">
    ```console
    pnpm graphics-publisher upload
    ```
  </TabItem>
  <TabItem label="Graphics kit" icon="laptop">
    ```console
    pnpm upload
    ```
  </TabItem>
</Tabs>

You'll be asked which [archives](/graphics-kit-publisher/sphinx/#archives) to upload:

```
◆  Which archives do you want to upload? (space to toggle)
│  ◻ reuters.com
│  │  ◻ public                        update
│  ◻ embeds
│  │  ◻ media-en-inflation-chart      update
│  │  ◻ media-en-jobs-map             new
```

Everything starts selected, so press enter to upload the whole pack.

Uploading a subset is worth it on packs with lots of embeds: the graphics server processes archives one at a time, taking a few minutes each, so re-uploading several embeds to fix one of them is several times the wait. The archives you skip are left untouched on the server, and any you've uploaded before go on serving — each archive carries [its own copy of everything it needs](/graphics-kit-publisher/sphinx/#interactive-editions).

Bear in mind a skipped archive keeps the version of your project it was last uploaded with. If a change should reach an embed, include it.

To skip the prompt -- in a script, or when you already know -- pass the archives you want, named exactly as the prompt shows them:

<Tabs>
  <TabItem label="CLI" icon="setting">
    ```console
    pnpm graphics-publisher upload --archives public,media-en-jobs-map
    ```
  </TabItem>
  <TabItem label="Graphics kit" icon="laptop">
    ```console
    pnpm upload --archives public,media-en-jobs-map
    ```
  </TabItem>
</Tabs>

In CI, with no `--archives`, every archive is uploaded.

<Aside type="tip">
**In a hurry?** To more quickly upload _just_ the `public` archive -- i.e., the page published on reuters.com, excluding all other embeds or editable editions -- run:

<Tabs>
<TabItem label="CLI" icon="setting">
  ```console
  pnpm graphics-publisher upload:quick
  ```
</TabItem>
<TabItem label="Graphics kit" icon="laptop">
  ```console
  pnpm upload:quick
  ```
</TabItem>
</Tabs>

**Note:** Your embeds and Connect editions keep serving the version they were last uploaded with, so run a normal upload sometime after a quick one to bring them up to date with your latest changes.
</Aside>

## Restart

Sometimes a graphic pack in the server gets mangled. Run this to remove existing pack IDs and URLs from `package.json`, allowing you to create a new pack next time you upload your project. This command will preserve all other pack metadata previously saved, e.g., titles, descriptions, etc.

```console
pnpm graphics-publisher restart
```

<Aside>
As a general rule, if your project hasn't published yet, you should use the [`delete`](#delete) command, which will also clear out all the previous pack's metadata from `package.json`.

If your project _has_ published, that isn't an option, so you can use this command.
</Aside>

## Delete

If possible, delete a graphic pack in the graphics server and restart the pack.

```console
pnpm graphics-publisher delete
```


<Aside>
Projects that have been published in the graphics server **cannot** be deleted.
</Aside>

## Diagnose

Re-open an AI diagnosis of the last command that failed. Handy when you dismissed the prompt, or want to look into a failure without re-running a slow command like a build.

```console
pnpm graphics-publisher diagnose
```

This reuses the diagnostics file written to `.graphics-kit/diagnostics/latest.md` on the last failure and offers the same [Claude Code handoff](/graphics-kit-publisher/config/ai/). See the [`ai`](/graphics-kit-publisher/config/ai/) config option for what the handoff does and how to turn it off.

<Aside>
If nothing has failed yet, there's no diagnostics file to open — run a command that fails first.
</Aside>
